Technical Design Document (TDD): Commodity Trading & ERP System
1. System Overview & Scope
1.1 Executive Summary
This Technical Design Document (TDD) outlines the structural layout, screen specifications, field-level validation rules, database persistence models, and end-to-end execution workflows for the Commodity Trading & ERP Management System.
The application manages the complete lifecycle of physical commodity trading—from core master entity configuration (Commodities, Weightment Terms, Brokers, Tax Structures, and Chart of Accounts) through Contract Execution, Despatch Tracking, and Bill Generation/Invoicing.

3. Mathematical Calculations & Business Logic Formulas
3.1 Base Contract Value
The total base transaction value $V_{\text{base}}$ for a given contract is computed as:
$$V_{\text{base}} = Q \times R$$
Where:
$Q$ = Total Contract Quantity (in M.T. or Quintals)
$R$ = Agreed Rate per unit currency
3.2 Goods & Services Tax (GST) Calculations
Tax application depends on whether the transaction is Intra-State (Seller State = Buyer State) or Inter-State (Seller State $\neq$ Buyer State):
Intra-State Supply (CGST + SGST):
$$\text{CGST Amount} = V_{\text{base}} \times \left( \frac{r_{\text{CGST}}}{100} \right)$$
$$\text{SGST Amount} = V_{\text{base}} \times \left( \frac{r_{\text{SGST}}}{100} \right)$$
$$\text{IGST Amount} = 0.00$$
Inter-State Supply (IGST):
$$\text{IGST Amount} = V_{\text{base}} \times \left( \frac{r_{\text{IGST}}}{100} \right)$$
$$\text{CGST Amount} = 0.00, \quad \text{SGST Amount} = 0.00$$
3.3 Gross Bill Amount
The final gross billing value $A_{\text{total}}$ is calculated as:
$$A_{\text{total}} = V_{\text{base}} + \text{IGST Amount} + \text{CGST Amount} + \text{SGST Amount}$$
3.4 Brokerage Commission Calculation
Brokerage liability $B_{\text{amount}}$ computed per contract/bill:
$$B_{\text{amount}} = Q_{\text{fulfilled}} \times R_{\text{brokerage}}$$
Where:
$Q_{\text{fulfilled}}$ = Actual fulfilled/despatched quantity
$R_{\text{brokerage}}$ = Brokerage commission rate per unit

Flow Walkthrough & Edge Case Protocols
Contract Initialization:
User navigates to SCR-CNT-06 and selects trade parameters.
Validation Check: The system confirms Seller ID $\neq$ Buyer ID.
On submit, status is set to CONTRACT_OPEN.
Fulfillment Tracking:
Dispatches recorded in SCR-DSP-07 link directly to the primary Contract No..
Tolerance Rule: Dispatches are allowed up to the contract limit plus the defined Quantity Allowance percentage (e.g., $(+/-)\ 5\%$). If exceeded, the system throws an inline exception: "Dispatch quantity exceeds contractual tolerance boundary."
Invoicing Execution:
Navigating to SCR-BIL-08, selecting a Party fetches all fulfilled, unbilled challan records within the specified From/To Date window.
The user clicks Select All and submits. The system creates an Invoicing Event, calculates applicable tax rates, and updates dispatch items to STATUS_BILLED.

6. Non-Functional & System Requirements
Transaction Concurrency: Database rows for contract quantity fulfillments must implement optimistic locking (@Version field) to prevent double-allocation during concurrent dispatch entries.
Audit Trail Compliance: Every CRUD action across screens records CreatedBy, CreatedTimestamp, ModifiedBy, and ModifiedTimestamp.
Printing & Dispatch Options: Integrated report generation engine (e.g., JasperReports / PDFkit) triggers layout renders when UI action buttons (Print, E-Mail) are executed.
